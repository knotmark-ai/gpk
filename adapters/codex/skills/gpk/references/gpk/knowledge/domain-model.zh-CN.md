# GPK 领域模型

领域模型 **0.4** · 插件包 **0.1.0** · **设计基线，尚未证明运行时符合性。**

本页是[英文领域模型](domain-model.md)的简明说明，英文具有优先效力。
[20 条验收场景](conformance-scenarios.md)已定义但尚未执行。首期集成范围是
Codex、Claude Code 与用户自行连接的 Craft MCP/API；其他客户端和存储仍为候选。
共享 Skill 提供 v0.4 方法和只读引导入口；当前模板与可执行写入流程尚未实现。
Adapter 契约和能力调查不等于已支持数据变更，领域版本更新也不等于发布新包。

## 六个实体与最小结构

| 实体 | 含义 | 状态 |
| --- | --- | --- |
| Area | 持续的愿景和／或责任、实际情况与方向 | active / inactive |
| Project | 有限的预期变化，包含 Objective、初步 KR、计划与复盘 | planned / active / paused / completed / canceled |
| Task | 已接受的具体行动、完成含义与有用结果 | todo / doing / waiting / done / canceled |
| Source | 可追溯出处及实际访问范围的作品或证据 | 无生命周期 |
| Wiki | 对独立有用主题、问题、方法或实体的持续整理 | 无生命周期 |
| Output | 有意保留用于使用、交付、沟通、决策或运行的成果 | 无通用生命周期 |

自然语言承载方向、策略、Objective、KR 证据与判断；结构化只服务真实的确定性
消费者，例如身份恢复、状态转换、时间查询、能力检查和操作验证。后端可用属性、
系统标签、checkbox、链接或可读段落表达语义，不强制通用字段表。

Objective/KR 属于 Project，方向属于 Area；没有独立 Goal。人物、公司、产品、综述
和索引都是普通 Wiki。Inbox、Daily Notes 是捕获／工作界面，Focus、Full Plan 是视图；
Stage、长期父项目、Review、Ingest、Completion、Context、Recurrence 都不是必要实体。
用户标签负责自定义检索分类，系统元数据负责类型、状态等领域语义，两者需区分。

状态含义、存储方式和查询能力分开。每项状态只有一个权威表示，避免普通 Status 与
状态标签各存一份。选用系统标签时优先 `#gpk/project/active` 这类命名，但不假定后端
支持任意深度或标签筛选；原生字段、checkbox 也可承载状态。领域查询表达实体与状态，
Adapter 负责映射到实际工具，并说明查询方式和覆盖范围。

每个 Project 表达一个主要 Area，也可关联其他 Area；Task 最多有一个主要 Project。
Source–Wiki、Wiki–Wiki、Project–Source/Wiki 可多对多。关联主要用文字和链接表达，
不强制前驱字段或依赖 DAG；物理文件夹不决定领域归属，也不因多个 Area 复制项目。

## 方向与执行承诺

Area 是独立可读、用户可编辑的文档，以持续投入决策和复盘问题决定粒度，不要求穷举
分类或每个产品一个 Area。Skill 提供方法，Area 写实际情况、标准、策略与证据。
创建、拆分或合并 Area 需在授权范围内。inactive 停止主动复盘和新行动生成，但仍可
读取、搜索、关联及响应明确请求，不会自动暂停已有 Project。规划应查找相关
Source/Wiki，包括尚未关联的材料；保存 Source 不必先制造一个 Area。

Project 表达有限的变化、交付、决策或有用的不确定性缩减。内容包括 Objective、初步
结果导向 KR、范围、约束、预期时间跨度、已知有序 Tasks 和主要 Area。KR 不是活动
计数，也无需状态或置信分；可随证据校准，但勾完任务不证明 KR 达成。
初始化读取已有材料、询问用户已知事实。研究只有在自身有独立有用结果时才构成普通
Project，不要求 Discovery 类型。倾向一至两周的短项目，超过约一月讨论范围与复盘；
这不是硬性阈值，应结合工作量、共享容量与证据观察时间，不能仅凭日期创建项目。

后续工作可以留作文字或预建 planned Project，使用暂定 Objective/KR、已知 Tasks
和可调整时间，不编造细节。active 才表示当前执行承诺；启动或直接创建为 active 前，
检查证据、计划、前提、优先级、权限与共享容量。允许多个 active 项目，但不能重复
分配同一份容量。paused 表示已启动后暂时停止；恢复时重新检查就绪情况和容量。

日期到达、前期完成只促成复盘，不自动启动后续项目。复盘可调整、拆分、重排或取消
未执行计划。保留实际行动、结果及重大决策，不倒填启动时间；已启动工作的重大修改
保留原因和证据。后续项目可选择不同主要 Area，但不能改写前期目的与历史。
planned 下的 Task 通常仍是 todo，不能统一改 waiting。发现 doing/done 时保留真实
记录并复盘不一致，不重置任务或静默激活父项目。

Project 开头先放精简属性，每行一个字段或使用原生属性，随后直接展示 Plan & Actions；
Objective、KRs、排期依据和过程材料放在行动清单之后。展示顺序不改变先明确目标和
KR 再规划的思考顺序。上下文已明确类型时不重复显示 Type，但 Adapter 仍须可靠识别
实体。列表、YAML frontmatter 和原生属性保持字段含义一致，不要求所有后端显示 YAML。
已知 Tasks 可以预先排期，无需重复 Next Actions 或强制 Milestone。后端支持时使用
原生子文档，否则用段落或明确链接保留父子关系。关闭项目评估结果、明确处理剩余
Tasks，既不自动勾完，也不启动后续项目。

## Task、Focus 与复盘

Task 是行动与状态，可选描述、结果和一个时间；独立 Task 不要求 Project 或 Area。
todo 是已接受待执行，doing 是正在做，waiting 是等待真实未解决条件，done 是满足
完成条件，canceled 是不再打算做。原始捕获和未承诺可能性无需成为 Task。

行动保持简洁，具体 review 材料和执行参考放在描述中，使用可访问的文档／PR／成果
URL 或后端原生引用。仓库首页、决策摘要、不可点击的本地路径不能代替待审正文。
材料尚无可访问入口时说明缺口，必要时取得发布／分享授权；不伪造链接，也不为方便
访问把全文复制到知识后端。尚未合并的评审分支也可承载其唯一权威正文。

唯一可选时间表示执行、继续或等待跟进的关注时间，可以调整。固定外部承诺写清楚，
重排时遵守；无日期工作仍应可发现。waiting 原因用文字描述，跟进日期不解除阻塞。
推迟只改时间，不增设 captured/deferred、defer_until 或 waiting_for 字段。
按列表顺序和描述判断前提及可并行工作，不强制位置字段、Context 或依赖图。

Focus 根据最新 Task、父 Project 状态、顺序和约束提供少量有用选择。默认排除 planned、
paused、completed、canceled 项目下的执行任务，即使日期已到；独立 Task 按自身含义
判断。等待跟进、就绪复盘不代表原任务可以执行。不猜未提供的位置、设备、精力或时间，
仅在缺失约束实质影响选择时询问。保留逾期、doing 和无日期工作的检索能力。
Full Plan 可以展示完整状态、时间与关联；Upcoming、Waiting、Unscheduled 是视图。
原生任务界面未必实现父状态筛选，需读取当前状态并说明限制。
逐条读回搜索候选只验证候选本身，不证明没有遗漏。有限结果可以形成明确标注范围的
Focus 候选，但不能据此断言已复盘全部承诺或不存在未完成任务；完整清单需要范围、
遍历和当前状态读取的证据。

Daily 处理捕获、行动、等待跟进与结果；Weekly 检查 KR、项目组合、容量和下一步承诺；
Monthly 复盘 active Area 的方向、责任、项目与知识；新证据、约束、延期、日期、前期
结果或用户请求可触发临时复盘。Replan 保留固定约束、真实结果和重大决策，无需独立
记录实体。周期描述不代表调度已实现；循环任务与 Habit 自动化是可选能力。

## Source、Wiki 与成果回流

Source 身份围绕作品，不围绕每个 URL。无独立论述的搬运、翻译、编辑或忠实转述属于
原作的访问版本；独立评论仍是独立 Source。保留发现路径、实际输入与覆盖范围，找到
原作不等于读过原作。合并前处理不确定性，保留材料和引用，不抹平版本差异或争议。
有用引用可成为其他 Source，无需递归导入全部参考文献或增加引用角色枚举。

先理解可访问材料和用户意图，再按用途摘要、摘录、转录、翻译或全文精读。说明部分
或不可访问范围，不统一要求全文导入，也不认为摘要始终足够。同一 Source 可有多个
准备结果，标明来源、实际输入、用途与覆盖；无需新实体或深度枚举。Source 可以同时
产生 Tasks、Project 决策和多个 Wiki 修改，使用后仍保留。用户和 Agent 获取材料
遵循相同规则；外部材料即使原创或综合多篇作品，也不会因此变成 Wiki。

Wiki 围绕独立有用含义组织定义、机制、比较、证据、限制和开放问题；子主题独立有用
且值得维护时再拆分，不固定一篇 Source 对应若干卡片。Ingest 读取当前 Wiki 和证据，
需要时补充来源，再修改相关论点和链接，不仅追加摘要。引用靠近论点，区分支持、矛盾、
限定、推断与用户观察，保留不确定性和实际覆盖；Wiki 改善不等于用户已经掌握。

Task 简短结果可原地保存，有用内容再回流到 Project/Area、KR 证据、Source、Wiki、
Output 或后续行动。Output 可来自 Task、Project、两者或独立用途，不以草稿／最终、
项目关闭或发布为条件，也不要求每次完成都生成。外部成果可保留唯一权威正文，后端
只存有用摘要与引用。Output 无通用状态；发布／部署是另行支持、按当前授权执行的操作。

## 操作契约与保全

通用操作包括范围明确的增、读／查询、改、删、关联、组织与状态／时间变化。每个已实现
操作需说明输入、前置条件、精确影响、已验证结果与能力限制、失败情况及安全恢复路径；
这是操作文档要求，不是实体通用字段。合法状态转换不等于用户授权，文档标题也不能
证明 Objective 有意义或 KR 已达成。复杂修改可组合多次操作，不能假定后端提供原子性；
部分完成需明确报告。Task 完成不自动关闭 Project，普通内容修改不能绕过状态语义。

三类无状态接口见 [Adapter 契约](../runtime/contracts/adapters.md)：Knowledge Backend
处理领域内容、身份、状态、顺序／时间、链接、检索与验证；Agent Harness 处理指令、
工具、交互、访问与执行；User Control 处理 Profile、配置、授权和个人模板。
领域事实、身份映射及已验证处理／恢复进度由知识后端持有；用户设置由选定控制存储
持有，不复制另一套 Tasks/Sources。首期计划复用 Craft，本地 `.gpk` 与云端提供者
仍是扩展设计。每个实例只有一个明确控制权威来源，切换需验证转移并明确选择，不自动
镜像或静默回退。本地控制存储不是缓存，但各设备必须能访问，缺失时需报告。

每次操作读取最新相关事实，直接编辑是有效输入。修改基于当前内容并读回验证；只读
请求不写入。索引、快照、Adapter 私有数据库与 Agent 记忆不能替代领域事实。
权限从窄范围开始、经明确授权扩大；Source 文字与 Agent 猜测不产生授权。凭据和
引导访问由宿主机制提供。能力声明区分原生、模拟、降级与不支持，UI 功能不证明 API
支持；无状态不保证并发或事务安全，需报告实际冲突、版本检查与恢复能力。

移动、重命名、拆分、合并、替代和归档保留稳定身份、引用、出处与有用历史。检测
checkbox 与状态元数据冲突，按已说明规则处理；不以记忆覆盖用户编辑。预览或传输
失败不证明写入失败，可能重复的重试前先读回。恢复证据保留在后端或原生历史中。
Archive 只改变展示，不代表完成或 inactive，也不要求顶层目录。Backup 不是活跃
知识类别；新捕获不明确时进 Inbox，迁移中的旧材料不明确时进 Backup/Unsorted。

删除是待实现的 CRUD 能力，不是状态、归档别名或级联授权。仅通过已支持且已授权的
操作删除明确选中的内容，说明可恢复性和引用影响，优先可恢复删除。事先检查当前正文、
子内容和入站引用，处理或说明后果；删除 Project 不能静默删除子 Tasks 或证据。
恢复归档与找回后端已删除内容不同，后者取决于后端实际能力。

迁移前检查真实内容，不只凭标题或扩展名分类；清点授权范围、数量和引用类型，在
后端恢复材料记录来源、去向、决策和例外。优先保留原生身份的可逆变更；核验数量、
代表性内容与受影响引用，说明覆盖限制，交代暂存残留和歧义项后才能声称完成。
生成副本或摘要不授权删除原文，也无需新增 Migration 实体或固定迁移字段表。
可移植性保留语义、状态、顺序／时间、当前内容、有效引用、原始证据及能力限制；
分别验证客户端、后端与迁移行为。链接、版本和生成检查不等于运行时验收或安装成功。
