# 架构与文档导航

状态：**领域设计 0.4；插件包 0.1.0 目前只有只读引导能力。**

本文是[英文架构](architecture.md)的中文辅助说明。产品定位与当前支持范围由
[README](../README.md)统一维护；本页说明职责边界与评审顺序。

## 职责与数据归属

| 层次 | 负责什么 |
|---|---|
| Domain | 实体、关系、状态、操作及约束 |
| Skills | 结合当前上下文理解意图、判断并编排操作 |
| Knowledge Backend Adapter | 将领域读取和变更映射到实际知识库能力 |
| User Control Adapter | 在选定控制存储中发现和维护用户资源 |
| Agent Harness Adapter | 加载指令，提供交互、工具、来源访问和执行能力 |

三类 Adapter 是独立接口，不要求三个服务或物理存储。首期目标是 Craft 知识库、
复用 Craft 的 User Control，以及 Claude Code/Codex 两个 Harness；完整配置与写入流程
仍待实现。本地控制目录和云端服务是后续 Provider，不代表已支持。

运行关系是请求或已授权触发进入 Agent/Skill，再按需通过 Control 读取当前用户资源、
通过 Backend 读取并操作领域事实、通过 Harness 使用实际工具。Markdown 提供指令，
有确定性消费者时才增加分页、编码、比较等辅助代码。

持久化事实由选定存储持有，Adapter 不保留权威状态。领域记录、来源身份和已验证处理
进度属于 Knowledge Backend；Profile、配置、个人模板和授权属于选定的 User Control。
凭据、最小连接信息与实际调度注册由宿主机制负责。换 Harness 后要从当前权威存储恢复，
访问不到就报告，不能隐式回退或创建另一份配置。

## 每个主题只有一份权威正文

英文为主稿，中文用于辅助阅读。架构页维护边界与导航，不重写领域、工作流或验收正文。

| 要评审的问题 | 唯一正文 |
|---|---|
| 产品为什么存在、服务谁、现在能做什么 | [README](../README.md) |
| 实体、关系、状态和操作含义 | [领域模型](../plugin/knowledge/domain-model.md)，[中文说明](../plugin/knowledge/domain-model.zh-CN.md) |
| 上下文、模板、五个 Skill、输入处理、执行与恢复 | [工作流契约](../plugin/runtime/contracts/workflows.md) |
| 三个接口和跨接口的公共数据 | [Adapter 契约](../plugin/runtime/contracts/adapters.md) |
| 具体产品的表示、证据和能力限制 | [Provider 映射入口](../adapters/README.md) |
| 领域、行为和实现需要通过哪些验收 | [统一验收清单](../plugin/knowledge/conformance-scenarios.md) |
| 文件组织、发现、打包和资源隔离 | [插件运行说明](plugin-runtime.md) |
| 当前基础能力怎样构建和本地加载 | [Getting started](getting-started.md) |
| 功能按什么顺序交付 | [Roadmap](roadmap.md) |

先评审领域操作与公共数据协议，再看三个 Adapter、上下文/模板/材料、Skill 与执行，
最后对照验收清单并核对具体 Provider 的证据。
修改要求时先改所属正文，再更新受影响的摘要、映射、Skill 和检查，不保留旧方案作为
第二份现行规则。生成包从源文件重新构建；实际能力不足必须说明，不能改写领域含义。

## 产品与私人上下文的边界

产品规范、设计、决策、Skills、模板、代码和测试，包括草稿，留在仓库并能独立评审。
正文说明产品问题、用户、范围、预期结果、取舍、实现、验证和交付，不要求访问私人笔记。

个人 Project 计划、用户信息、研究历史和复盘留在选定知识库。仓库不带入所有者真实的
Area 归属、个人愿景、责任、财务动机、私人 OKR 或时间分配。通用 Area 模型及虚构示例
可以解释；删除私人链接或改写措辞不等于获得公开个人背景的依据。

私人知识可以链接仓库成果；仓库不能反向依赖私人笔记的 URL、ID、标题、个人路径或
“参见私人文档”的指示。产品需要的获准背景和推理直接写入正文，引用仓库或公开来源。

每份成果保留一个权威正文，产生它的 Project/Task 记录有用摘要与成果或修订链接。
临时上下文只是当前输入，不成为第二份项目、任务或控制数据库。

## 当前实现与验证

当前生效的 `gpk` 读取共享 bootstrap 和领域规则，对限定材料做解释或只读评估。
五个业务 Skill、共享步骤和默认模板占位不生效，不代表契约已实现。

包检查证明生成一致性、元数据和独立资源解析；真实操作、工作流判断和跨 Harness
可移植性需要分别验证，并记录在统一验收清单中。新集成有实际 Adapter 和相应验收证据
后才能宣称支持。源文件保持在 `plugin/`，Codex 包由构建器生成到 `adapters/codex/`。
